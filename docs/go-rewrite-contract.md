# Enclava Go Application Contract

This documents the selected Go application as composed today. It is an implementation reference, not a deployment, security-certification, or compliance claim. The Python plugin subsystem and legacy SQLite/import runtime are not part of this application.

## Runtime and data ownership

`cmd/enclava` composes one application: PostgreSQL stores tenant-scoped identity, source metadata, jobs, reservations and usage; the configured durable filesystem stores artifacts; configured inference endpoints are reached through the shared `internal/inference` executor. SQLite metadata storage and SQLite migrations have been removed. A working deployment needs an operator-provided PostgreSQL DSN and durable data directory; RAG/search additionally needs Qdrant. External OIDC and upstream inference require configured, reachable services and valid credentials.

Local users, roles, credentials, API keys and sessions are tenant-owned PostgreSQL records. Local account creation is administrator-controlled through the bootstrap/identity flows; there is no public signup. OIDC identities are bound by issuer and subject, and account linking requires an authenticated explicit flow. Session revocation is checked server-side. Public API credentials are verified against stored identity rows; request-supplied tenant/actor fields do not establish authority. Cookie-authenticated mutations use CSRF protection.

## Structured document processing and previews

The canonical parser in `internal/extract` accepts plain text, Markdown, HTML, CSV, XLSX, JSON/JSONL, DOCX, PDF, and PNG images. PDF processing uses Poppler (`pdfinfo`, `pdftotext -bbox`, and `pdftoppm`); OCR uses Tesseract with installed language data. Startup probes the required `bubblewrap`/`prlimit` sandbox, Poppler binaries, Tesseract, and available OCR languages. Missing tools or isolation do not stop startup, but affected PDF/OCR work returns an explicit unavailable error instead of fabricated extraction. Encrypted PDFs are reported as such rather than parsed silently. Text input that is not valid UTF-8 is decoded as UTF-16 or windows-1252 with a decoding warning instead of failing; XLSX sheets over the cell cap emit a `truncated:` warning.

Native children run with a cleared environment, no network namespace, read-only system binaries, and only a private scratch directory writable. `prlimit` bounds CPU to 30 seconds, address space to 512 MiB, child processes to 16, and individual files to 16 MiB; native output is capped at 16 MiB. PDF input is capped at 100 pages and image input at 40 million pixels. Parser input is capped at 32 MiB; preview uploads use `MAX_UPLOAD_SIZE_MB` (default 15 MiB) and remain subject to the parser limit. DOCX expanded content and preview result reads are capped at 64 MiB.

Asynchronous extraction and image recognition use `POST /api/v1/extract/jobs` with one multipart `file`, `template_id`, and optional `operation` (`extract.process` or `extract.vision`; the UI uses `image-recognition` for the vision operation). The endpoint returns `202` with `job_id`, initial `status`, and `status_url`; `GET /api/v1/extract/jobs?limit=&offset=` lists only caller-visible jobs, and `GET /api/v1/extract/jobs/{id}` returns current status and, once available, the result. `GET /api/v1/extract/jobs/{id}/result` reads the result, `GET /api/v1/extract/jobs/{id}/original` downloads the retained input, `POST /api/v1/extract/jobs/{id}/cancel` requests cancellation, and `DELETE /api/v1/extract/jobs/{id}` cancels active work first and deletes the job's owned artifacts after work is terminal. Unknown and unauthorized identifiers share a not-found response. An omitted idempotency key is derived from template and input hash; supplied keys are scoped by tenant and operation, identical submissions replay, and changed input/policy with the same key conflicts. Inputs and outputs have no automatic expiry and remain until explicitly deleted; the jobs audit row remains after artifact deletion.

Uploads are limited by `MAX_UPLOAD_SIZE_MB` (default 15 MiB) and accept PDF, JPG/JPEG, PNG, TXT, Markdown, HTML, CSV, JSON, and DOCX; image recognition requires an image. Model selection resolves the template override, tenant default, or a model attached to an enabled endpoint with the required explicit capability. Local processing requires the parser's native tools and isolation where applicable; confidential routing requires a configured provider that verifies its supported assurance, and is never inferred from endpoint location or model name. Output schema validation is local and versioned (the result reports `schema_version`), but only checks schema conformance—it does not establish factual correctness. Results are generated output with validation feedback and usage; processing does not automatically publish knowledge or index anything. Qdrant is not required for this job lifecycle.

The related authenticated configuration routes are `GET/POST /api/v1/extract/templates`, `GET/PUT/DELETE /api/v1/extract/templates/{id}`, `POST /api/v1/extract/templates/reset-defaults`, `GET /api/v1/extract/models`, `GET/PUT /api/v1/extract/settings`, and `GET /api/v1/extract/health`. API keys require the `extract` scope for these routes except template reset, which requires `extract.manage`. The dashboard uses its authenticated session and CSRF protection for mutations.

Chunk profiles are immutable versions: `id` identifies the version, while `profile_id` and `version` identify its family and sequence. Profile size and overlap are Unicode code points, not bytes or tokens. Result spans are UTF-8 byte ranges within extracted block text, not offsets into the original compressed file; page, clause, table, parent, thread, and line locations are shown only when the parser has them. Preview uses the same parser and chunker as downstream processing.

Table-aware chunking leads every CSV/XLSX table chunk with its header rows and packs rows to the profile size; a document is capped at 4,096 chunks and records a `truncated:` warning on the last kept chunk when it exceeds the cap.


Authenticated profile reads are `GET /api/v1/document-profiles` and `GET /api/v1/document-profiles/{immutable_version_id}`. The preview lifecycle is `POST /api/v1/document-previews` (bounded multipart `file` plus `chunk_profile_version_id`), `GET /api/v1/document-previews/{id}` (queued/running/succeeded/failed/cancelled/unknown status), `GET /api/v1/document-previews/{id}/result`, `GET /api/v1/document-previews/{id}/original` (owner-authorized retained upload), and `POST /api/v1/document-previews/{id}/cancel`. These owner-scoped routes use durable jobs and artifacts and do not require Qdrant or an inference endpoint. `/dashboard/documents` is an authenticated embedded review surface; it only reads/selects existing versions and submits previews. Profile creation and edits remain API-only.

## Knowledge retrieval

Collections store per-generation `query_prefix` and `passage_prefix` taken from a per-model registry at create/update (Qwen3-Embedding and instruct E5 get the Qwen3 retrieval instruction on queries; nomic-embed-text, e5 and bge/arctic/mxbai families get their conventional prefixes). `passage_prefix`, `embedding_model`, `embedding_dimensions` and `embed_titles` changes move embedding to a new index and re-embed; `query_prefix` applies to new queries without re-embedding. Embedded text is `passage_prefix + title + chunk`, plus scalar metadata only while it stays under roughly a quarter of the chunk size; titles come from connector-provided metadata or the filename (chat-message objects carry no title), whitespace-normalized and capped at 120 runes. BM25 searches the `search_text` payload (title + chunk + keyword metadata). Re-embedding runs as a durable `rag.reembed_scan` job whose progress is visible to collection managers; stored chunks are reused when the chunk profile is unchanged, and parse/chunk warnings persisted per generation are returned on documents. Retired indexes are deleted only after `INDEX_RETIREMENT_SOAK` (default `24h`) has elapsed since they left use, and a replacement index is adopted only after a point-count canary succeeds.

Search does not enumerate and authorize every published document per query. Indexed points carry `acl` tokens and a `published` flag; the prefilter uses caller tokens for actor, delegated actor, tenant-wide access, mapped source identities and source groups from a complete membership snapshot. Every hit is re-authorized against PostgreSQL for the object, version, document status and current published generation before results, evidence, locations or facets are produced. Revocation is immediate, and temporary connection disablement is enforced by the post-check rather than the tokens. Each index fetches four times its result limit, capped at 200 points per round, for at most three rounds (initial plus two extra); post-check drops can leave fewer results.

Access tokens are written during embedding and refreshed before publication. Complete grants snapshots re-project connector objects under revision fencing. The durable `rag.access_backfill` job backfills points indexed before this projection, enqueued at startup and by a periodic trigger; unprojected points remain searchable through the post-check.

During a model switch, search fuses per-index rankings using plain (unweighted) reciprocal rank fusion. A binding whose model the caller may not use is skipped; if no binding can be searched, search fails. `POST /api/v1/rag/search` and `POST /api/v1/rag/collections/{id}/search` accept `rewrite` and `select_sections` flags served by the configured utility model (`UTILITY_MODEL`); unconfigured they fail with `utility_model_not_configured` (HTTP 400). Query embedding and rewrite are query-only; section selection sends its candidate results' source references with the model call, subject to input restrictions.

Cross-collection search has no per-collection or aggregate 2,000-document bound. `POST /api/v1/rag/search` returns `search_scope_too_large` for more than 20 distinct requested collections, or more than 20 readable collections when no selection is supplied.

## Selected public inference API

Only these public inference paths are mounted; there is no generic upstream catch-all or `/api/v1` inference alias:

- `GET /v1/models` and `GET /v1/models/{model_id}`
- `POST /v1/chat/completions` (unary and streaming where supported by the endpoint)
- `POST /v1/embeddings`
- Responses lifecycle routes under `/v1/responses`: create/stream, retrieve, delete, cancel, input items, input-token calculation and compact

All model calls use the shared executor and its authenticated principal, endpoint/model authorization, admission and accounting. Responses references are bound to their local tenant/owner/endpoint context. Unsupported operations, model capabilities and unsafe resource shapes are rejected; the service does not fabricate provider responses. Provider-specific behavior still requires validation against the configured upstream. `openai.proxy` is not a general-purpose passthrough permission and does not mount additional products.

The app also mounts tenant-scoped provider/endpoint metadata and processing-restriction controls, RAG, prompt-template, chatbot, connector, and extraction routes. These are described in the route matrix; the presence of a route or a deterministic test does not demonstrate real connector permissions, retrieval quality, external identity, or upstream interoperability.

## Connector sources and access rights

Connector sync (`connector.sync` jobs) runs three durable streams — content, access-grants and memberships — each with its own listing checkpoint. A source config change resets the stream cursor and run boundary, so the next sync re-lists from the start. Unchanged content produces no new version unless the ingest handoff is missing or name/title/URI/mime metadata changed. Access snapshots count `unmapped_principals` (provider accounts without an Enclava binding get no access), stub unknown objects and accept deny-everyone grants — Drive files flagged copy/download-restricted are denied for everyone that way. Authorization inherits grants along parent objects (Slack channels, GitHub repositories, Teams channels/chats) and requires membership only for group grants; complete grant and membership snapshots both expire after `SOURCE_ACCESS_MAX_STALE`. Sync credentials themselves never grant readers access.


## Assistants, conversations and approved tools

`/dashboard/chatbots` configures tenant assistants (model, optional provider route, prompt template, permitted collections and tool IDs) and provides a live conversation view. `POST /api/v1/agent-runs` starts a durable asynchronous run; `GET` and `DELETE /api/v1/agent-runs/{id}` read status or request cancellation. `GET /api/v1/conversations/{id}` returns the authorized conversation. Run execution uses the shared inference executor, authorized RAG evidence, bounded tool iterations and current approval checks; configured MCP tool IDs alone do not grant authority. MCP discovery is not approval, and only explicitly approved/current tools with matching schema and server configuration can execute. The MCP administrator screen exposes server and approval configuration; secrets are not exposed to assistant configuration.

Run status is asynchronous and cancellation is a request, not proof that an already-dispatched upstream operation has stopped. Evidence resolution is rechecked on run/conversation reads so revoked evidence is not reusable. Extraction built-ins enqueue the existing authorized job lifecycle; they do not run extraction inline. Provider availability, confidential assurance and external MCP reachability depend on configured live services and are not inferred from model names or UI selections.

Run execution is a bounded turn loop: the last turn is always dispatched with tools removed (a final no-tools turn), a tool call or an empty answer on that turn fails the run, and mid-run tool errors are returned to the model as tool output while authorization errors still abort. Model-facing tool names are sanitized to `[a-zA-Z0-9_-]` and de-duplicated with suffixes; the assembled context is trimmed to the model's discovered context window before dispatch. The default prompt template places retrieved RAG context in the user turn. Assistant messages are reserved before dispatch and finalized `complete` or `interrupted` (`reserved`/`interrupted` rows stay out of served conversation history).

## Identity, ownership and authorization

Every operation uses the verified tenant and actor from the authenticated principal. Durable resources are owner- or audience-scoped, and authorization is enforced by the owning service/repository path. Unknown and forbidden resource identifiers are intended to have the same public outcome. Provider credentials are resolved from operator-configured secret bindings for an approved tenant, purpose and origin; public configuration does not accept secret values or turn a user-supplied environment-variable name into a secret lookup.

Password changes rewrite the bcrypt hash and atomically revoke the user's other sessions — only the session performing the change survives. Dashboard sign-in is throttled per process (10 attempts/minute per IP, 5 per 15 minutes per account with a 4,096-bucket cap) with a dummy-bcrypt compare on failures. Security-relevant mutations append to a security audit log readable at `GET /api/v1/admin/security-audit` (`platform.admin`; `limit` 1–200, `before` cursor; actions such as `auth.login.succeeded`/`failed`/`throttled`, `auth.password.changed`, `auth.sessions.revoked`, `apikey.*`, `identity.*`, `endpoint.*`, `connector.source.*`, `mcp.server.*`, `mcp.tool.*`).

## Operator configuration and observability

Durable job handlers run under a per-job deadline (`JOB_TIMEOUT`, default `2h`); expiry fails the handler and frees the worker slot. `GET /metrics` requires `Authorization: Bearer $METRICS_TOKEN` and fails closed when no token is configured unless `METRICS_AUTH_DISABLED=true` disables auth. Additional knobs: `SOURCE_ACCESS_MAX_STALE` (default `168h`) bounds the age of complete grant and membership snapshots for source authorization; `UTILITY_MODEL` (default empty) selects the model used by search `rewrite`/`select_sections`; `INDEX_RETIREMENT_SOAK` (default `24h`) delays retired-index deletion. All are defined in `internal/config/config.go` and documented in `.env.example`.

Local login, OIDC provider setup, and upstream endpoint credentials are external operator prerequisites. OIDC login/linking against a real identity provider was not exercised as part of this source-only cutover. The Go tests cover deterministic local flows and protocol cases, not a claim of live IdP availability.

## Pricing, reservations and capacity

Money is stored as signed integer currency-micros, with an explicit currency. A configured rate is `rate_micros` per `unit_quantity` for a named billable unit. The selected accounting units are input, output and cached input; cached input is a subset settled separately from uncached input. Price snapshots preserve every selected rational rate, currency and rounding rule (ceiling); no implicit free unit or foreign-exchange conversion is assumed. A priced attempt reserves checked per-unit quantities and a monetary ceiling before dispatch. Unknown upstream outcomes retain their hold; settlement uses the immutable reservation snapshot and raw reported usage.

PostgreSQL reservations enforce applicable tenant and billing-subject budget limits across processes. HTTP/upstream admission limits (active work, queue depth/bytes and stream bounds) are process-local configuration and are not a distributed concurrency guarantee. Cancellation/disconnect releases local work resources and propagates cancellation; it does not prove that an already-dispatched upstream operation had no side effect. Do not infer multi-process capacity bounds from the database accounting limit.

## Capability and assurance boundaries

An endpoint is usable only for its configured protocol, capabilities, origin, credentials and authorization. A configured private endpoint is not automatically confidential; ordinary TLS is not attestation. Attested/confidential assurance is reported only when the selected provider supports and verifies it. Failed required verification denies dispatch. The application makes no guarantee about endpoint availability, provider data handling, deployment hardening, or regulatory compliance.
## Option A dashboard (v1.1)

The dashboard is the Option A grouped-sidebar surface: server-rendered Go templates (`templates/app/`), htmx fragments, one hand-written stylesheet (`app.css`) and one shared client (`app.js` exposing `window.Enclava`). There are no redirects or aliases from the retired URLs; the old templates, scripts, styles and smoke tooling are deleted. Dashboard handlers only render — every write is a `fetch` to `/api/v1` with the session cookie and CSRF header.

Authorization is server-enforced through one capability table (`internal/httpx/dashboard_caps.go`): each capability mirrors the scope gate of the `/api/v1` route serving the same data, `platform.admin` grants no feature capability, and every page/partial registers through `requireCap`/`capSession` (session → CSRF → capability). Templates read only the per-request `Caps` booleans; hiding a control is presentation, the API check is the authority. Unknown `/dashboard/*` paths render the 404 page.

Role-bound AI resources (models, endpoints, assistants, extraction templates) are explicit stored allowlists on roles (`{"mode":"all"/"list"}` documents, migration 023); session authority is the union of the assigned roles' grants — never an implicit `platform.admin`. Default seeded roles: Admin (all scopes + mode:all), Knowledge manager and Member (explicit empty grants — deny by default until an admin grants). Key issuance and re-arming (create/patch/regenerate/restore and any activation) is bounded by the caller's resource authority; pure deactivation stays free.

New screen-facing reads/writes added in v1.1: `GET /api/v1/conversations` (own-only keyset), run steps + observed route on run reads, `POST /api/v1/agent-runs` accepting server-resolved `evidence_ids`, `GET /api/v1/rag/evidence/{id}/passage`, `POST /api/v1/rag/search` (bounded cross-collection, explicit `search_scope_too_large` above the 20-collection bound), multipart `POST /api/v1/rag/collections/{id}/documents`, `?status=` document filtering with soft-delete `removed`, `PATCH`/`DELETE /api/v1/identities/roles/{id}` (atomic last-admin protection), `POST`/`PATCH /api/v1/admin/budgets`, and the durable MCP discovery queue with versioned approvals (409 on stale review). Home attention/activity aggregates read only source-authorized service projections — `rag.manage` never bypasses source ACLs.

## Current verification evidence and prerequisites

`go build ./...` succeeds. With the supplied PostgreSQL and Qdrant test services, `go test -count=1 ./...` passes all packages except the external OpenAI SDK contract test, which requires `OPENAI_CONTRACT_BASE_URL`, `OPENAI_CONTRACT_API_KEY`, and chat, embedding, and Responses model names. `ENCLAVA_PROXY_INTEGRATION=1 go test -count=1 ./tests -run TestProxyTwoProcess` passes against its controlled upstream and shared PostgreSQL fixture; this proves the in-repository two-process admission/accounting scenario, not compatibility with an external inference service. The selected app/identity/provider/usage browser scenarios, real OIDC linking, and a real external inference contract need configured live services and must be run in the post-merge application harness. Missing those prerequisites is not a pass. Keep phase-2 document-processing, phase-3 knowledge-quality, and later connector/agent capability claims separate from these core tests.

`.github/workflows/ci.yml` runs the same build/test suite on pull requests and `main` pushes with PostgreSQL/Qdrant service containers plus golangci-lint v2 (new issues only). Engineering checks enforced by tests include the route-auth completeness test (`internal/httpx/route_auth_test.go`), the real-adapter ACL pipeline test (`internal/connectors/acl_pipeline_test.go`), and the docs path test (`tests/docs_paths_test.go`); the cross-cutting checklists live in `docs/cross-cutting.md`.
